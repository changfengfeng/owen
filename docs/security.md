# 安全边界和威胁模型

## 不可信内容

用户 prompt、公开仓库、模型输出、工具参数和执行结果都不可信。系统提示里的限制仅用于指导模型，**不构成安全隔离**；真正的边界是 gVisor、宿主配置、容器资源限制和不向任务注入密钥。

## 控制面

认证采用 scrypt 密码散列、随机服务端会话、只保存 session token 散列、HttpOnly/SameSite=Strict Cookie、CSRF header 和 origin 校验。用户内容只通过 textContent 渲染，前端使用严格 CSP。所有任务、事件、补丁、取消和额度 API 均按会话租户过滤。生产注册需要运维注册码；这不是无需审核的匿名注册服务，也不具备反机器人或邮箱所有权验证。

认证节流同时按可信客户端 IP 和邮箱散列记录。反向代理必须正确配置来源信任。HTTP 请求大小默认 128 KiB，模型上下文、工具输出、补丁和 archive 解包均有大小限制。还需要基础设施层的全局请求限流、连接数限制、DDoS 防护和管理员操作审计。

## 执行面

- gVisor `runsc`，没有生产 runc fallback。
- 非 root UID 1000；只读容器根文件系统；workspace 和 /tmp 使用有大小限制的 tmpfs。
- 默认无网络、无宿主挂载、无 Docker socket、无 LLM/平台密钥。
- 删除全部 Linux capabilities，启用 no-new-privileges，限制 CPU、内存、PID。
- Worker 在宿主侧下载公开 GitHub 默认分支 archive；只允许固定 codeload 主机，不跟随重定向，不读取代理环境变量。
- 限制下载 20 MiB、解压 100 MiB、10,000 个条目；拒绝路径穿越、Git 元数据、符号链接、硬链接及设备等特殊条目。
- patch 相对 Worker 保存的初始 commit ID 生成，避免模型自行提交后丢失 diff；工作区在结束后销毁，仅保留补丁与事件。

gVisor 也不是绝对防逃逸保障。必须持续更新宿主内核、Docker、gVisor 和基础镜像；高敏感或强对抗场景建议使用独立执行主机或 microVM，并另行评估跨租户侧信道与沙箱逃逸风险。

## 模型和凭据

LLM 密钥只由可信 Worker 使用，API 和任务容器不接收。代码和工具结果会发送给配置的模型供应商，部署者需要评估数据处理条款；不要提交真实凭据或敏感代码。该首版不支持将 GitHub token 暴露给任务，也不提供私有仓库授权。

数据库 URL 含数据库凭据，Worker 拥有 Docker 主机权限，二者都属于可信运维边界。保护 `.env`、数据库备份和容器配置，避免在终端输出 `docker compose config` 的完整结果或把 Docker inspect 输出上传到公共渠道。

## 未覆盖的生产能力

第三方安全审计、账户恢复、邮箱验证、MFA、支付、精确供应商账单、跨主机执行节点调度、KMS、自动保留清理、灾难恢复自动化、全局限流和操作审计尚未实现。不要把这里的安全默认值解释为已经完成这些能力。
